# 03 — Découpage en étapes

Chaque étape se termine par un build de développement installable sur ton téléphone (EAS Build profil `development`, puis Expo Go n'est pas possible à cause de RevenueCat et expo-blur natifs à partir de l'étape 1). Un build de dev se réinstalle rarement : les étapes suivantes se chargent par rechargement JS, sauf ajout de module natif (signalé dans la colonne « Build natif »).

À la fin de chaque étape je te donne : ce qui est fait, comment tester, ce qui reste.

## Ce qui est prévu dans l'architecture sans être codé (hors V1)

- **Import Instagram** : `post_media.storage_path` et `posts.source` (colonne à ajouter, enum `manual | instagram`) ; une Edge Function d'import plus tard.
- **Lives** : `shops.live_playback_id` + Mux Live. Rien à prévoir en base maintenant.
- **Paiement entre utilisateurs** : `conversations` et `posts.status` sont le bon point d'accroche ; une table `orders` viendra à côté sans toucher l'existant.
- **Version web** : Expo Router rend déjà sur le web ; le design system évite les API natives dans les composants de base. Le blur a un fallback.
